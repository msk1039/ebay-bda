2-MINUTE TALK (about 1.5 minutes spoken). Use slides 2, 7 and 9; the rest are backup for the viva.

Why Big Data matters: eBay's data outgrew one database. It has 300 million searches a day, and in 2009 its log warehouse took in 150 billion new records a day. That is Volume, Velocity and Variety together.

Why Hadoop is needed: relational warehouses like Teradata and Greenplum scale up and need a fixed schema. Hadoop scales out on cheap nodes and keeps three copies of every block.

Which Hadoop component stores data: HDFS. YARN schedules resources and MapReduce processes the data, for example building eBay's search indexes.

Which NoSQL we recommend: HBase for Hadoop-linked work, because it sits on HDFS and MapReduce can bulk-load it. eBay also uses Cassandra for fast writes and MongoDB for flexible product data.

Industry application: e-commerce - search, recommendations and fraud detection. The mind map shows how every Unit 1 and Unit 2 topic connects through eBay's pipeline, with seven cross-links.

--- speaker notes ---
VIVA - Why can't RDBMS handle Big Data efficiently? (1) It scales up on bigger machines, which gets expensive and hits a ceiling; (2) it needs a fixed schema, so semi-structured logs and images fit badly - eBay packed name=value text into one SQL column; (3) heavy joins over huge tables are slow. A distributed system scales out by adding commodity nodes and tolerates node failure. Note: eBay did not drop SQL; in 2010 it ran Teradata (10+ PB) beside Hadoop, and one analyst reported eBay then saw Hadoop as limited for joins.

--- speaker notes ---
VIVA - Role of HDFS: distributed storage; a file is split into 128-256 MB blocks held on DataNodes, while the NameNode keeps the map of which blocks belong to which file. Why replication: each block has 3 copies on different machines, so a failed node loses no data and reads can be served from another copy. YARN: the cluster's resource manager - the Resource Manager hands out CPU and memory, Node Managers run the tasks - and it lets Spark, Storm and Tez share the cluster with MapReduce. MapReduce example from eBay: count searches per query - Map emits (query, 1) for every search, Reduce adds them up. eBay uses MapReduce to build its Cassini search indexes. How does eBay use Hadoop: store (HDFS, hundreds of PB), schedule (YARN), process (MapReduce, Hive, Spark) and feed HBase, Cassandra and MongoDB.

6
--- speaker notes ---
VIVA - HBase vs MongoDB: HBase is a wide-column store built on HDFS, with row-key lookups and range scans, strong consistency per row, and bulk loading from MapReduce - best for Hadoop-linked, huge, sparse tables. MongoDB is a document store (JSON-like documents) with a flexible schema and rich queries, with its own replication and sharding - best for varied catalogue-style data. Cassandra is a masterless wide-column store tuned for very fast writes across many nodes. Which would we recommend: HBase for Hadoop-linked workloads (eBay's Cassini search and Kylin OLAP both use it); the course's e-commerce hint points to MongoDB for the product catalogue. CAUTION: the MongoDB row comes from summaries of an eBay talk (MongoDB at eBay) that we have not read in full - check it before presenting.
